# Night context optimization

Queue `name|pane` lines in `ORCHESTRA_STATE/otimizacao/fila.txt`. Schedule `otimizacao_noturna` every ten minutes; use `--status` to inspect. Starts are limited to 21:00–04:59 and usage below `OTIM_MAX` (default 75%). Stale/missing cache data must block dispatch. `PAUSA` blocks new work; one active space is retained until `<name>.feito` exists. A timeout logs a warning and holds the queue rather than overlapping agents. `ORCHESTRA_PRIORITY_PANES` can delay optimization while important sessions work. `LIVRE_NOITE` is an explicit date-scoped override.

The receiving agent must save before/after byte counts and use this procedure: checkpoint Git; preserve every rule; move long procedures to docs with pointers; keep CONTINUIDADE near 40 lines; consolidate duplicate memory without losing facts; move uncertain material into `_discard/<date>/` with a manifest; update the project knowledge graph and Obsidian export incrementally when configured; ask three real project questions to verify retrieval; compare old rules against the new docs; commit and write the completion marker with changes and pending work. Never launch, stop or modify calculations as part of optimization. Sensitive unpublished or personal data must not be sent to free external models.

`fila_prioridade_noite` is a different queue for authorized agent work, not computation. Configure `NIGHT_PRIORITY_CONFIG` using `night-priority.example.json`; create `night-priority/queue.json` as `[{"space":"sample-alpha","pane":"w2:p1"}]` under its configured state directory. It starts one idle agent, gates fresh usage, and waits for `night-priority/<space>.feito`. `--status` inspects, `--dry-run` previews. No timeout automatically releases an active agent. All launch commands are argv lists. Do not configure the sender as the queue executable itself.
