# Set up a multi-agent project workspace

[Português brasileiro](MONTAR_ARQUITETURA_CLAUDE.pt-BR.md)

This guide builds on the generic orchestration kit and upstream harness. Treat each optional integration as a separate installation decision; checking out this repository does not change global settings.

1. **Inventory first.** Inspect OS, shell, available RAM, CPU cores and installed tools. Check existing workspaces and project instructions; preserve work already prepared. Select the project roots, preferred language and authorized scope.
2. **Terminal and agents.** Install herdr and the needed agent CLIs using their official instructions. Verify the installed CLI help and JSON envelope against this kit. One workspace per repository, named tabs, distinct agent names and the same project cwd. Start secondary interactive agents only when needed. Existing session history can be resumed; a new project needs a fresh session.
3. **Central coordinator.** Use [the central template](../orquestra/templates/CLAUDE.md) and [shared permanent instructions](../orquestra/templates/BLOCOS_PERMANENTES.md). Maintain a map of projects and agents. Distinguish permanent instructions from one-off requests, retry busy agents later, and keep delivery evidence in project state.
4. **Project harness.** Use [preparar-space](../orquestra/skills/preparar-space/SKILL.md). Fill `project.yaml`, initialize UAH and compile. Preserve the existing approval gates. Keep the project goal, protected data, resource quotas and next action explicit.
5. **Continuity and resources.** Maintain `state/current.md`; optional `state/current.json` records whether jobs are running. `modo` stores presence without granting permissions. Configure MGE-LocalCompute on shared PCs; keep admission and thermal limits in its configuration, without hardcoding the hardware in project instructions.
6. **Deterministic monitoring.** Create stable `vigia_status.sh` event summaries. Read [VIGIA](VIGIA.md), test with `--dry-run`, then schedule only within the authorized scope. Preview `retomar_apos_limite.sh ... --once --dry-run` before enabling automatic prompts. Its text detection depends on the agent display format.
7. **Economical auxiliary work.** Simple nonsensitive summaries can use short model calls; scientific conclusions need independent evidence. Configure Groq credentials and model via environment variables. Prefer one-shot commands to idle interactive sessions.
8. **Optional integrations.** Verify source, license and need before enabling OMC, graph indexing, document tools or knowledge vaults. Prepare exclusions before indexing large files or private data. Do not republish third-party skills without checking their licensing.
9. **Delivery and remote access.** `_handoff/` plus acknowledgment manifests separates pending delivery from `.sent/` archives. Configure notifications through environment variables; quiet hours always force low priority. Remote access, firewall changes and exposing the portal require their own authorized setup; consult the sibling portal's security documentation.
10. **Validation.** Check workspace names, tabs, cwd, instructions, checkpoints, harness compilation, resource limits and offline kit tests. Record evidence, unresolved items and next steps before declaring the installation ready. Use independent review where the project's risk justifies it.
